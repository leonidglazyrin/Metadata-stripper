# Sharona · creator tools

A web app for creators:

- **Strip metadata** from photos and videos (EXIF, GPS, XMP, IPTC, ICC, C2PA, container tags), with optional SynthID watermark disruption.
- **Download** videos (or just the audio) from **YouTube**, **X**, **Instagram** and **TikTok** links.
- **Accounts and plans**: Google sign-in, 1 free on-device strip, 1 free server strip and 1 free download per account. Then **Basic at $10/month** (unlimited on-device stripping) or **Pro at $20/month** (everything, including faster server stripping and downloads) via Stripe. Setup: [docs/accounts-and-billing.md](docs/accounts-and-billing.md).

## Pages

| Path    | What it is |
|---------|------------|
| `/`     | Landing page (`web/index.html` + `web/src/landing/`). Rendered to static HTML at build time, no JS. |
| `/es/`, `/pt/`, `/fr/`, `/de/`, `/ru/`, `/ja/`, `/ko/`, `/tr/`, `/id/` | The landing page in other languages, each with its own title, description, hreflang alternates and JSON-LD. Copy lives in `web/src/landing/i18n/` (one file per language); add a language there and in `LANGS`. |
| `/app/` | The tools (`web/app/index.html` + React app). Old links like `/#youtube` redirect to `/app/#youtube`. |
| `/guides/`, `/guides/<slug>/` | How-to guides (metadata/privacy and video downloads), English only. Content lives in `web/src/pages/guides.ts`; a new entry there gets its page, sitemap entry, footer link and JSON-LD automatically. |
| `/privacy/`, `/terms/` | Privacy Policy and Terms of Service (`web/src/pages/legal.ts`). Drafts: have them legally reviewed. |
| `/robots.txt`, `/sitemap.xml` | Generated by the server. |

Set `SITE_URL` (for example `https://sharona.example`) in production so canonical, Open Graph, JSON-LD and sitemap links use your real domain. Without it the server uses the request's host.

## Architecture

```
web/        React + Vite frontend (TypeScript)      → builds to dist/
server/     Node + Express API                      → serves /api/* and dist/
  index.js        /api/strip (sharp + ffmpeg)
  downloaders.js  /api/download/:platform (yt-dlp)
  account.js      Google sign-in, quota, Stripe Checkout / Portal / webhook
  store.js        Supabase (Postgres): users, usage, subscriptions
```

Vite + React is the **frontend only**. The backend stays a Node service because the work it does needs native tools: `sharp`/libvips for images, `ffmpeg`/`ffprobe` for video, and `yt-dlp` (Python) for downloads. None of those run on edge runtimes like Cloudflare Workers, so the API ships as a container (see `Dockerfile`). Accounts and billing live in the same server and store their data in Supabase (Postgres), so the container is stateless and needs no disk.

## Server or on-device stripping

The stripper has a **Server / This device** switch.

- **Server** uploads the file, cleans it with sharp/ffmpeg and deletes it right after. It handles every format.
- **This device** never uploads anything:
  - **JPEG, PNG, WebP, GIF** are cleaned losslessly: metadata blocks (EXIF, XMP, IPTC, comments, text chunks, MPF trailers, non-essential app extensions) are cut out and the compressed image data is copied byte for byte. Rotated photos and non-sRGB color profiles are re-encoded through a canvas so they still look right.
  - **HEIC/HEIF** is decoded with libheif (wasm, loaded on demand) and saved as JPEG; **AVIF** and other formats the browser can decode are saved as PNG.
  - **Videos** are remuxed with ffmpeg.wasm using the same options as the server (`-map_metadata -1`, data tracks dropped, SEI filtered, `-c copy`). The ~30 MB engine is self-hosted and downloaded once; files up to ~1.8 GB.
  - **SynthID mode for videos** applies the server's filter chain (`gblur=sigma=0.3`, temporal luma noise, luma `unsharp`) to every frame and re-encodes. It uses WebCodecs through [Mediabunny](https://mediabunny.dev) in a worker, so decoding and encoding run on the GPU's media engine where the device has one, and the filter runs directly on the decoded YUV planes (no RGB round trip). Output is MP4 (H.264, or HEVC/VP9/AV1 if H.264 encoding isn't available) or WebM for WebM input, with AAC or Opus audio at 256 kb/s. Browsers without WebCodecs, and containers Mediabunny can't read (AVI, WMV, FLV…), fall back to ffmpeg.wasm with the server's exact arguments, which is several times slower. The fast path holds the output in memory, so it's capped at 1.5 GB input.

## What gets removed

**Images** (JPEG, PNG, WebP, HEIC/HEIF, AVIF, TIFF, GIF) are decoded to raw pixels and re-encoded into a fresh file, so nothing from the original container survives: EXIF (camera, serial numbers, timestamps, GPS), XMP, IPTC / Photoshop IRB, ICC profiles (converted to sRGB first), C2PA / Content Credentials (JUMBF), MPF, maker notes, embedded thumbnails, PNG/GIF text comments. EXIF orientation is applied to the pixels first so images stay upright. HEIC is output as JPEG.

**Videos** (MP4, MOV, M4V, MKV, WebM, AVI, MTS/M2TS, TS, 3GP, WMV, FLV) are remuxed with ffmpeg:
- only real video/audio/subtitle streams are kept; data tracks (GPS/telemetry, timecode, camera metadata), attachments and cover art are dropped
- all global, per-stream and chapter metadata is removed
- unknown boxes such as C2PA `uuid` manifests are not carried over
- H.264/HEVC SEI user-data units (encoder strings) are filtered from the bitstream
- streams are copied losslessly unless SynthID stripping is on; if a codec can't go back into its original container the output is MKV

Each result shows what was detected and removed.

## Downloads

| Platform  | Accepted links | Notes |
|-----------|----------------|-------|
| YouTube   | `youtube.com` (watch, Shorts), `youtu.be` | MP4 (H.264 + AAC) up to 1080p |
| X         | `x.com`, `twitter.com` | The video attached to a post |
| Instagram | `instagram.com` (Reels, video posts) | Public posts only, private videos aren't available |
| TikTok    | `tiktok.com`, `vm.`/`vt.` short links | |

Each tool can save **video** or **audio only** (M4A). Links are checked against each platform's domains, so the API can't be used to fetch arbitrary URLs. `POST /api/tiktok` still works for older clients.

Only download content you own or have permission to use. Downloading can break a platform's terms of service, and you are responsible for how the app is used.

## Running

Requires Node.js 22.13+ with `ffmpeg`/`ffprobe` and `yt-dlp` on `PATH` (`brew install ffmpeg yt-dlp`, or `pip install yt-dlp`; the server also tries `python3 -m yt_dlp`, or set `YTDLP_PATH`). Keep yt-dlp updated, since platforms change often.

```bash
npm install
npm run dev        # Vite on http://localhost:5173, API on :3000 (proxied)

npm run build      # type-check + build the frontend into dist/
npm start          # API + built frontend on http://localhost:3000
npm test           # server tests (accounts, quota, Google and Stripe mocked)
```

In dev, sign-in and upgrades are simulated until you set the Google and Stripe variables (see [docs/accounts-and-billing.md](docs/accounts-and-billing.md) and `.env.example`).

The terminal running the server logs every download (platform, mode, link, file, size, time) and every strip (file name, mode, size before → after, time, what was removed), plus failures. Set `NO_COLOR=1` to turn off colors.

```
17:47:35 strip    OK   "photo.jpg" → photo_clean.jpg [image, metadata only, q100] 1.2 KB → 563 B in 22ms · removed: EXIF, ICC color profile
17:48:02 download OK   YouTube video https://www.youtube.com/watch?v=… → Channel_id.mp4 (24.3 MB) in 6.1s
```

Or with Docker (ffmpeg and yt-dlp included):

```bash
docker build -t sharona .
docker run -p 3000:3000 --env-file .env sharona
```

### Environment variables

| Variable | Default | |
|----------|---------|---|
| `PORT` | `3000` | |
| `CONTACT_EMAIL` | `support@<SITE_URL host>` | Contact address shown on the Privacy Policy and Terms |
| `MAX_UPLOAD_MB` | `2048` | Max upload for the stripper |
| `MAX_DOWNLOAD_MB` | `2048` | Max file size yt-dlp will fetch |
| `DOWNLOAD_TTL_MIN` | `30` | How long a finished download stays on the server, so a reloaded page can still collect it |
| `DOWNLOAD_STALL_MIN` | `5` | A download with no yt-dlp output for this long is killed as hung |
| `DOWNLOAD_MAX_MIN` | `30` | Hard cap on one download's run time |
| `YTDLP_PATH` | | Path to yt-dlp if not on `PATH` |
| `YTDLP_IPV6` | | Set to `1` to let yt-dlp use IPv6. By default it's forced to IPv4, because on networks with broken IPv6 yt-dlp hangs for minutes with no output |
| `ALLOWED_ORIGINS` | | Comma-separated origins allowed to call the API when the frontend is hosted elsewhere |
| `VITE_API_URL` | | Build-time: API base URL if the frontend is hosted separately (must be the same site, e.g. `api.example.com` for `example.com`, so the session cookie is sent) |
| `SESSION_SECRET` | random per start | **Required in production.** Signs the session cookie |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | (required unless `PAYWALL=off`) | Supabase project for accounts, subscriptions and usage. See `docs/accounts-and-billing.md` |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | | Google sign-in |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | | Stripe API key and webhook signing secret |
| `STRIPE_PRICE_ID_BASIC`, `STRIPE_PRICE_ID_PRO` | | The $10 Basic and $20 Pro monthly prices. The webhook maps each price to its plan. `STRIPE_PRICE_ID` is the old name of the Pro one |
| `PAYWALL` | on | `off` disables sign-in and limits |
| `FREE_STRIPS`, `FREE_SERVER_STRIPS`, `FREE_DOWNLOADS` | from the `app_settings` table (1, 1, 1) | Free on-device strips, server strips and downloads per account. Leave unset to manage them in Supabase without a deploy |
| `PRICE_LABEL_BASIC`, `PRICE_LABEL_PRO` | `$10`, `$20` | Prices shown in the upgrade dialog (the charge itself comes from the Stripe prices) |
| `TRUST_PROXY` | private ranges | Express `trust proxy`, so `https` is detected behind a load balancer |

Uploads are written to a temp directory and deleted as soon as the response is sent. Finished link downloads stay for `DOWNLOAD_TTL_MIN` minutes so a reloaded page can collect them again (removing the row deletes them sooner). The server purges the temp directory on startup and sweeps it every minute for expired, hung or orphaned files, and logs why each download failed (yt-dlp's exit code and its ERROR / WARNING lines).
